# Proposal

## Why

現有網站已能保存題材判讀、指標與版本，但閱讀仍夾雜識別碼、原始狀態與大數值，圖上的供應方向也混入需求回饋。下一步應讓研究者能從產業角色、技術限制與可回溯文件理解一條關係為何成立，再以可量測的讀取流程支援個人及小群研究。

## What Changes

依下列優先順序交付：

1. **改善閱讀層次**：一般畫面優先使用中文名稱；移除一般閱讀中的內部識別碼、原始列舉與錯誤診斷；依研究任務分頁，避免技術欄位、監測資訊與原文重複堆疊。證據程度統一顯示「有明確證據支持／有條件推論／仍待核實」，數值依單位、幣別及口徑顯示易讀尺度，仍可查原值。
2. **釐清產業關係**：圖與文字清單區分供應關係及需求回饋；可選連線閱讀供應項目或需求機制、介面依賴、成立條件、證據與缺口。保留真實回路、三種影響遍歷、跨產業導覽、返回分享、手機與鍵盤操作。
3. **深化技術與供應鏈研究**：先補強散熱、電源與供電架構、互連、網通與光通訊、先進封裝，再完成其餘環節；全部 17 環節與 7 題材都要能辨認產品邊界、採用條件、瓶頸、替代限制及證據缺口。技術相容、供應能力、客戶導入及收入證據分開判讀。
4. **加入權威技術文件與版本追蹤**：優先評估 OCP、OIF、UCIe、IEEE IRDS 與 JEDEC 公開資料；逐文件確認免費可讀範圍、文件性質、版本及適用範圍。取得文件更新只建立待核對候選，人工核對及 Markdown 修訂後才改變研究，不自動提升商業化判定。
5. **改善資料讀取效率**：合併相同 API 請求、按需載入歷史比較；覆蓋統計、最新觀測與樣本限制交由 SQL 執行，訂定可失效的快取策略。以 10 位同時讀取者建立可重現基準，驗證暖機後常用 API p95 < 500ms、覆蓋摘要 p95 < 1 秒的目標。

## Capabilities

### New Capabilities

- `technical-document-tracking`：技術文件身分、版本觀測、待核對狀態及研究引用基準；重跑不產生假更新，失敗不刪除既有證據。

### Modified Capabilities

- `industry-explorer`：中文閱讀層次、證據與數值呈現、可選取且可解釋的關係，以及按需載入與請求合併。
- `industry-map`：具型別的環節關係、可回溯技術論述與全圖研究覆蓋；維持既有結構及離線遍歷契約。
- `information-sources`：以單一來源註冊表納入技術文件入口，區分文件性質、免費範圍、可讀性及實際擷取狀態。
- `data-coverage`：以 API 與維護報告保存逐環節／題材的技術證據、版本待核對與研究缺口；一般閱讀只呈現與論述相關的引用及限制；保留既有事件及指標計數語意。
- `platform-runtime`：SQL 有界讀取、快取新鮮度、10 位讀取者效能基準與失敗／重跑驗證。

## Impact

- 前置基準為 `b613d53` 的 `add-evidence-based-theme-assessments` 已完成成果；該 change 保持未歸檔。本 change 不修改其 artifacts，也不在本輪 sync 主 specs；後續歸檔順序必須先前置 change、再本 change。
- 預計影響 `industry-map/README.md`、環節／題材 Markdown、`sources.yaml`、validator 與測試，以及 backend 的 graph／import／research／assessment／indicator／update 查詢、additive migrations、Prefect 文件觀測流程；frontend 的 API hook、圖、閱讀、版本及來源／覆蓋頁同步更新。
- 既有公開唯讀 API、URL、ticker、三種遍歷及此裝置關注行為相容；新文件資料走 additive 投影與只讀 API。研究維護仍透過 Markdown 與本機維護指令。
- 沿用 Next.js、FastAPI、PostgreSQL、Cytoscape.js 與 Prefect。本階段不新增 Redis、圖資料庫、微服務、付費資料、帳號、行情或 AI 摘要，也不進行公開部署。
- 上述效能數字是待實測驗收目標，並非現有容量保證；需記錄硬體、資料規模、查詢分布、快取狀態及測試結果。規劃完成後另行啟動 apply。
