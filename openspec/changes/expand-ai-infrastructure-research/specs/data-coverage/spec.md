# Spec Delta

## ADDED Requirements

### Requirement: 擴充研究以逐項證據矩陣驗收

維護者 MUST 能取得三方向各自的可保存交付矩陣，逐項記錄產品／角色／公司、五個研究面向的閱讀位置、主張與來源定位、適用範圍、查核日、具體缺口及驗收結果。矩陣 MUST 區分分類存在、證據完成、內容審閱與網站閱讀驗收，不以檔案數、連線數或測試通過取代內容判定。

#### Scenario: 公司證據存在但產品研究仍薄弱
- **WHEN** 產品已連到有證據的公司，但產品的原理、規格或替代條件仍只有通用描述
- **THEN** 矩陣分別標示公司能力與產品研究狀態，產品深化仍列未完成

#### Scenario: 已完成一個方向
- **WHEN** 某方向的實作任務被勾選為完成
- **THEN** 可從任務連到逐項驗收結果、已讀來源、剩餘缺口及實際閱讀紀錄

### Requirement: 已查核缺口與未完成工作不得混同

研究 MUST 區分未研究、未公開、未取得與不適用。已查核而確實缺乏公開資料可作為交付限制，但未讀來源、整頁占位或未執行的必要驗收 MUST 保持未完成。來源無法取得時 MUST 記錄嘗試與可用替代證據；不得以缺口文字消除尚未履行的核心研究要求。

#### Scenario: 沒有公開具名客戶
- **WHEN** 原理、產品能力與採用條件已有證據，但官方資料未揭露客戶名稱
- **THEN** 可在保留查核依據與缺口的前提下完成相應研究，不捏造客戶，也不宣稱具名供應已確認

#### Scenario: 核心原理只有待查文字
- **WHEN** 核心產品用途與技術差異尚未查核，只填寫未取得或未研究
- **THEN** 核心產品研究仍不得判定完成；需要補查或經明確範圍修訂處理

### Requirement: 研究交付能核對預覽發布與公開版本

三方向整體交付 MUST 記錄被審閱的內容提交及研究版本，使應用、產品、公司、來源與比較在同一版本可連續閱讀。驗收 MUST 區分檔案驗證、隔離預覽、正式研究發布與公開快照；未執行的後續狀態不得標為成功，舊版研究及連結仍須保留可追溯性。

#### Scenario: 程式已部署但研究尚未發布
- **WHEN** 程式部署完成，正式研究 head 仍指向舊版本
- **THEN** 紀錄明示研究尚未發布，不把部署成功當作三方向已可供讀者閱讀

#### Scenario: 公開快照仍是舊研究版本
- **WHEN** 私人服務已有新版研究，但公開靜態快照尚未更新
- **THEN** 私人發布與公開發布分別記錄版本及結果，不宣稱公開網站已含新增研究
