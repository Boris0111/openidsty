# Spec Delta

## Purpose

將免費官方公告、法說資料與基本財報整理為具來源及時間的事件資料，維持公司識別、財報口徑、更新健康狀態與重跑一致性，確保後續圖形與摘要有可驗證的資訊基礎。

## ADDED Requirements

### Requirement: 官方資訊可追溯

系統 MUST 優先介接台美官方公告、公司 IR／法說與財報資訊；每個事件 MUST 保留來源文件識別、URL、發布時間、取得時間及原始資料。來源只回外殼或無內容時 MUST 視為失敗，不得當作成功擷取。

#### Scenario: 官方資料與外殼頁面
- **WHEN** 來源回傳可解析公告
- **THEN** 建立可點回來源的事件
- **AND** 若只回 JavaScript 外殼，來源狀態顯示未成功，既有資料仍保留

### Requirement: 重跑一致與來源隔離

同一來源文件重跑 MUST 不重複建立事件與財報；某來源失敗 MUST 不阻止其他來源成功，並保留最後嘗試、最後成功、錯誤原因及新增筆數。不同來源未確認同一事件時不得僅憑標題合併。

#### Scenario: 部分來源失敗後重試
- **WHEN** 一來源逾時而其他來源成功，下一輪重跑
- **THEN** 保留失敗狀態並只加入尚未存在的資料

### Requirement: 公司對應保守且支援中文

系統 MUST 以發行公司或官方識別欄位決定事件主體，並支援中文別名與英文 token 邊界。正文提及公司 MUST 與主體、圖形推導公司分開，不得依 tier 將被提及的大廠升格為主體。

#### Scenario: 中文與英文名稱比對
- **WHEN** 文字出現台積電、臺積電、NVIDIA 或 AMD
- **THEN** 可對應正確 ticker
- **AND** AMD 不得因出現在較長英文單字內而誤命中

### Requirement: 來源檢查與離線測試

系統 MUST 提供單次擷取及來源健康查詢；測試 MUST 可用離線 fixtures 驗證解析、去重、財報口徑與失敗行為。公開站 MUST 不將測試 fixtures 當成即時資料發布。

#### Scenario: 未取得資料
- **WHEN** 所有外部來源暫時失效
- **THEN** 網站仍顯示地圖與既有內容，並明確顯示資料缺口與來源狀態
