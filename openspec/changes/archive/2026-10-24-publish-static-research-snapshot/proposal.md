# Proposal

## Why

研究服務目前只綁 127.0.0.1，要公開分享就得讓一台常開的機器對外服務：一個人維運的負擔太重，資料庫與後台也會暴露在網路上。2026-10-23 的產品重新定位已決定，第一版公開只放**研究結構**（環節地圖、題材判讀、公司角色與關係、供應鏈），以靜態快照放在免費 CDN；這部分內容都是自寫或已標授權，轉載風險最低。公司財報已在上一個 change 移除，現在可以開始做公開版。

## What Changes

- **新增靜態快照匯出**：從**一個已發布的研究版本**，把讀者閱讀研究結構所需的 API 回應匯出成 JSON 檔與圖解檔。
  - 匯出直接呼叫既有 API 的處理函式，回應內容與正式服務相同，不另寫一套查詢。
  - 依「公開內容邊界」剝除動態與維運欄位：
    - 事件與事件候選。
    - 來源的執行狀態。
- **新增靜態網站建置**：前端以 Next.js `output: 'export'` 另建一份「公開快照版」。
  - 資料改從快照檔讀取，不需要任何伺服器、API 或資料庫。
  - 搜尋、目錄篩選與公司比較的組合無法逐一預先算好，改由前端用快照內的索引組出結果；排序與篩選名單仍由後端匯出，前端不重寫篩選語意。
- **公開版只呈現研究結構**：
  - 移除事件、傳聞觀察、題材指標、判讀版本歷史、此裝置收藏、資料覆蓋、來源狀態與後台的入口。
  - 頁面固定顯示快照的研究版本、發布日期與「不構成投資建議」。
- **新增部署與回復流程**：
  - 輸出目錄附 `_headers`（安全標頭、快取規則），可用 Cloudflare Pages 或 Netlify 的直接上傳部署。
  - 部署由維護者在發布研究後手動執行；回復方式是重新部署前一份快照。
- **自動檢查**：CI 以 fixture 快照建置公開版，逐頁瀏覽，確認三件事：
  - 沒有缺漏的快照資料。
  - 沒有對 `/api` 的網路請求。
  - 手機寬度不水平溢出。
- **正式服務不變**：私人研究服務、排程、後台與 `reader` gateway 照常運作；這次只新增一條離線匯出路徑。

## Capabilities

### New Capabilities

- `public-research-snapshot`：已發布研究的公開靜態快照，涵蓋以下五項。
  - 內容邊界：公開什麼、不公開什麼。
  - 與研究版本的對應。
  - 不依賴後端的閱讀行為：搜尋、篩選、比較、缺漏處理。
  - 免責與版本標示。
  - 建置驗證、部署與回復。

### Modified Capabilities

- `platform-runtime`：「可重現啟動與持久化」原本寫明「本版供本機及私人網路使用」，改為：
  - 動態服務仍只供本機及私人網路使用。
  - 另允許不含伺服器的公開靜態快照。

## Impact

- **後端**：新增匯出模組（在 API 容器內執行，唯讀連線研究資料庫）。不新增或修改任何 API、資料表與 migration。
- **前端**：
  - 新增快照資料轉接層（`fetch` 前的路徑對應與搜尋、篩選、比較的本地計算）。
  - 新增公開版的導覽、頁尾與功能開關。
  - 動態路由（題材、公司代號）補上靜態產生參數。
  - 新增 `build:static` 腳本與靜態 E2E 測試。
  - 原本的 standalone 建置與行為不變。
- **營運**：
  - `scripts/research_lab.py` 新增匯出指令。
  - 新增部署文件 `docs/public-snapshot.md`。
  - README 補公開快照步驟。
- **CI**：新增公開版建置與靜態 E2E 步驟。
- **外部服務**：Cloudflare Pages（或 Netlify）免費方案，需要維護者自己的帳號；第一次公開部署要由維護者確認後才執行。
- **不在範圍內**：
  - 事件公開（另開 `publish-events-feed`）。
  - 自訂網域。
  - 發布後自動部署。
  - 草稿效能（`improve-draft-editing-performance`）。
  - 地圖廣度擴充。
