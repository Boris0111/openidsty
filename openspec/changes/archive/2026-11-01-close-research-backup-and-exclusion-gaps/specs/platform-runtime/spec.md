# Spec Delta

## MODIFIED Requirements

### Requirement: 故障可恢復且不偽裝新鮮度

來源失敗 MUST 保留最後有效資料，發布失敗 MUST 保留舊研究；資料庫不可用時 MUST 回傳可重試的服務不可用狀態，不假造空資料成功。系統 MUST 定期備份資料庫、排程元件自己的資料庫、研究 Git 歷史與資產，並能在獨立環境核對還原；排程元件升版之前的部署前備份 MUST 保留為回退邊界，例行清理 MUST NOT 刪除它。祕密設定不得隨公開研究或收藏備份流出。

#### Scenario: 資料庫故障
- **WHEN** 讀取 API 無法連線資料庫
- **THEN** 回傳服務不可用及請求識別，畫面保留已成功載入的內容並說明目前無法更新

#### Scenario: 隔離還原演練
- **WHEN** 維護者從備份建立新的還原環境
- **THEN** 能核對正式研究版本、歷史、數值修訂與資產，不覆寫原資料庫

#### Scenario: 備份涵蓋排程元件的資料庫
- **WHEN** 每日備份或部署前備份完成
- **THEN** 備份含排程元件自己的資料庫，並記錄它的遷移版本與排程、執行紀錄的筆數
- **AND** 在獨立還原環境還原後，遷移版本與筆數和備份記錄相符

#### Scenario: 排程元件升版後要回到舊版
- **WHEN** 某次部署升級了排程元件，之後維護者需要回到升級前的版本
- **THEN** 回退被拒絕，並指出升級前的部署前備份；這份備份仍在，同時含研究資料庫與排程元件的資料庫，可依事故程序還原

#### Scenario: 較舊的備份沒有排程元件的資料庫
- **WHEN** 從本規則生效前的備份建立還原環境
- **THEN** 研究資料照常還原與核對，報告註明這份備份沒有排程元件的資料庫

### Requirement: 新舊開發環境相互隔離

正式研究服務 MUST 使用獨立的容器 project、image、network、資料庫、volumes 與執行憑證，並占用原服務的讀者 origin（web `127.0.0.1:3010`、API `127.0.0.1:8010`、Prefect `127.0.0.1:4201`）；原服務 MUST 保留可回復的 image 與資料，但 MUST NOT 與正式研究服務同時運行。任何會啟動、替換或回退正式研究服務的操作，包括啟用排程，MUST 先確認原服務沒有任何容器在運行、目標 port 未被占用，否則拒絕並說明原因，不得自動停止或刪除原服務。還原演練環境 MUST 使用自己的 project 與 port，不得占用正式 port。還原／遷移只在明確指定的研究資料庫執行；Git 分支回退不得被視為已還原資料庫。

#### Scenario: 預覽新版並保留原服務
- **WHEN** 啟動、重建或停止正式研究服務或還原演練環境
- **THEN** 原服務的容器、image、資料與連線保持原狀

#### Scenario: 原服務仍在運行時啟動正式服務
- **WHEN** 原服務仍有容器在運行或 3010／8010／4201 被占用，並嘗試啟動正式研究服務
- **THEN** 操作拒絕並指出占用者，原服務的容器、image、資料與連線保持原狀

#### Scenario: 原服務仍在運行時啟用排程或回退
- **WHEN** 原服務仍有容器在運行或共用 port 被占用，維護者嘗試啟用正式研究服務的排程，或回退正式研究服務
- **THEN** 操作在改變任何狀態前拒絕並指出占用者，兩邊不會同時抓取官方來源

#### Scenario: 在原 origin 閱讀
- **WHEN** 讀者在切換後開啟 `http://127.0.0.1:3010` 的舊 ticker 深連結、舊題材網址或含 `#candidates` 的連結
- **THEN** 由正式研究服務回應並解析到對應頁面，`#candidates` 轉到「數據與追蹤」，同一 origin 的 v1 題材收藏只遷移一次且 v1 原值保留

#### Scenario: 回復原服務
- **WHEN** 停止正式研究服務並以原 image 啟動原服務
- **THEN** 原服務使用原資料回到 3010，正式研究服務的 volumes 保留，不執行 destructive downgrade
