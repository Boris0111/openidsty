## ADDED Requirements

### Requirement: 版本控制內容可完整重現公開入口
專案 MUST 僅憑版本控制的乾淨 checkout 與文件中的本機設定重現公開入口；忽略規則不得排除必要應用原始碼。自動檢查 MUST 驗證地圖、後端離線測試、前端型別／建置及主要導覽，與真實外部來源擷取分開；正式 runtime 不得載入測試 fixtures。

#### Scenario: 資料覆蓋頁與產物同名
- **WHEN** 乾淨 checkout 建置網站並開啟資料覆蓋入口
- **THEN** 該頁原始碼在版本控制中，入口可載入，測試 coverage 產物仍可忽略

### Requirement: 來源配置與恢復結果可驗證
維護文件 MUST 提供 SEC 真實聯絡設定、官方來源失敗分類、單來源重試及結果核對方法。缺少配置與 HTTP／解析失敗 MUST 分開顯示；無法恢復的來源 MUST 保留既有資料及實際限制。配置與恢復不得重置其他服務或以外殼回應宣稱成功。

#### Scenario: SEC 尚未設定且官方 IR 持續封鎖
- **WHEN** 維護者檢查未配置的 SEC 與回傳 HTTP 403 的 IR
- **THEN** 可辨識各自處理方式，重試仍失敗時留下來源限制，其他來源及研究仍可使用
