# Spec Delta

## MODIFIED Requirements

### Requirement: 覆蓋矩陣與缺口

系統 MUST 向維護者提供所有環節、題材、公司及產品的研究覆蓋、來源能力與實際成功、最近更新、近 30／90 日直接事件及分類樣本。背景統計、公司提及、未知發布日與 inference MUST 分開計數；未研究、未公開、未取得與不適用 MUST 可區分。一般閱讀只呈現與當前主張有關的限制，維護矩陣與診斷不作為主要閱讀入口。

#### Scenario: 某環節沒有直接事件
- **WHEN** 來源只有公司財報、背景統計或尚未成功
- **THEN** 該環節的直接事件數為零，保留研究與實際缺口，來源診斷由維護者查閱

### Requirement: 回補與持續更新

系統 MUST 首次嘗試回補來源可提供的近 90 日事件，其後每小時檢查到期更新；財務歷史依來源實際可取得範圍回補。維護者 MUST 可查看實際範圍、分頁限制及部分失敗，讀者可辨識顯示數值的期間；不得宣稱未取得的歷史已完整回補。

#### Scenario: 來源僅提供有限 RSS 歷史
- **WHEN** 回補到 feed 或分頁的歷史上限
- **THEN** 報告實際範圍與限制，後續重跑不重複建立事件

### Requirement: 技術研究覆蓋與文件待核對獨立呈現

管理 coverage 與可保存維護報告 MUST 對所有目前環節及題材列出：技術研究面向是否整理、已核對文件版本、查核日與論述定位、待核對候選及處理狀態、具體缺口，以及未研究／未公開／未取得／不適用的區分；來源失效時 MUST 保留既有研究與查核基準。技術文件數、來源設定數、新聞量或代理指標有值 MUST NOT 被當成研究完整或論述已核實；沒有技術證據的面向 MUST 可明示尚待補強。一般閱讀 MUST 保留影響判斷的具體研究限制，例如來源只支持產品能力、尚不能確認具名客戶採用；候選數量、parser 錯誤與維護進度 MUST 只在管理端呈現。

#### Scenario: 有新聞但缺少替代限制證據
- **WHEN** 某環節已有近期直接事件而替代條件尚無可核對文件
- **THEN** 事件數照實呈現，技術研究面向保留缺口，不因有新聞而標為完成

#### Scenario: 原研究引用舊版文件
- **WHEN** 文件監測發現尚未核對的新版本
- **THEN** 管理 coverage 同時保存既有已核對基準與待核對候選及處理狀態；一般閱讀不展示維護佇列，不將研究查核日期改成取得日

#### Scenario: 讀者閱讀能力證據有限的公司
- **WHEN** 已發布研究只有產品能力證據，尚無具名客戶採用
- **THEN** 一般閱讀在該主張旁說明此限制，不顯示候選數或維護進度

## ADDED Requirements

### Requirement: 交付以研究可用性驗收

全鏈交付 MUST 保留既有全部環節、題材、公司及歷史，逐環節檢查產品分類、供應角色、代表公司與引用；首批五領域 26 家深研 MUST 逐家公司人工檢閱。產品分類缺口不得用公司數或圖上連線數掩蓋；未知客戶可保留已核對限制，不得用空白模板或 UI 字體改動宣稱完成內容深化。

#### Scenario: 頁面欄位齊全但沒有可用研究
- **WHEN** 深研公司頁只有標題、通用敘述與未查核占位內容
- **THEN** 交付矩陣標為未完成，直到產品用途、業務界線、風險與引用完成實質檢閱
