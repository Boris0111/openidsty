## MODIFIED Requirements

### Requirement: 官方資訊可追溯
系統 MUST 介接免費官方資料、產業媒體及背景統計；每個事件 MUST 保留來源識別、URL、原始資料與取得時間。發布日、出表日、活動日 MUST 分開，未知發布日 MUST 保留空值，日期精度為日時 MUST 不顯示午夜。沒有單一公司事件 MUST 允許空 ticker；只有外殼或無內容 MUST 視為失敗。

#### Scenario: 官方資料與外殼頁面
- **WHEN** 來源回傳可解析公告
- **THEN** 建立可點回來源的事件
- **AND** 若只回 JavaScript 外殼，來源狀態顯示未成功，既有資料仍保留

#### Scenario: 出表日與活動日期
- **WHEN** 台灣財報只有出表日期或 IR 只有活動日期
- **THEN** 不將該日期宣稱為真正發布日，取得時間另行保留

### Requirement: 重跑一致與來源隔離
同一來源文件重跑 MUST 不重複建立事件與財報；同一提供者的跨 feed 文章 MUST 以 canonical URL 去重，統計報告 MUST 依資料集與期別識別。某來源失敗 MUST 不阻止其他來源成功，並保留最後嘗試、最後成功、錯誤原因及新增筆數。不同提供者未確認同一事件時不得僅憑標題合併。

#### Scenario: 部分來源失敗後重試
- **WHEN** 一來源逾時而其他來源成功，下一輪重跑
- **THEN** 保留失敗狀態並只加入尚未存在的資料

#### Scenario: 跨 feed 與統計修訂
- **WHEN** 同一科技新報文章出現在兩個 feed，或同一期報告更新
- **THEN** 不建立重複事件，保留來源與期別

## ADDED Requirements

### Requirement: 全範圍內容分類與影響起點
系統 MUST 為全部環節及題材建立中英文規則，保留命中詞、摘錄及版本。直接相關、背景統計與公司提及 MUST 分開；例行財報與軟體誤命中 MUST 排除直接分類，首頁 MUST 優先產業變化。影響推導 MUST 從直接內容分類開始，不得以公司的全部角色取代內容起點。

#### Scenario: 只有公司名稱
- **WHEN** 文章提及台積電但沒有產業技術內容，或 AMD 出現於 AMDOCS
- **THEN** 不因此建立直接環節事件；英文名稱遵守 token 邊界

#### Scenario: 真實分類與排除
- **WHEN** 離線驗證真實文章
- **THEN** 全部環節與題材有正例，並測試誤命中、中文別名、英文邊界與例行財報／軟體排除
