# Spec Delta

## ADDED Requirements

### Requirement: 一般讀取有界且保留既有資料語意

常用 API MUST 只回傳請求所需的分頁或樣本，總數與筆數限制 MUST 在取得結果前生效；結果 MUST 保持原分類、日期、期別、修訂與排序定義。覆蓋摘要 MUST 不因加入較舊歷史就返回全部原始事件或觀測。效能最佳化 MUST 不截斷影響候選、隱藏未知日期或把缺少資料變成零。

#### Scenario: 增加歷史觀測與事件
- **WHEN** 資料庫累積更多舊事件及指標修訂
- **THEN** 摘要維持有界回應，分頁總數及最新有效修訂正確
- **AND** 同一資料快照上的 30／90 日計數、直接分類與既有樣本定義不變

### Requirement: 快取可重新取得且新鮮度有界

快取 MUST 依資源及查詢參數隔離，研究與覆蓋快取的新鮮度上限 MUST 明文記錄且不超過 60 秒；重新取得 MUST 可略過快取。失敗回應 MUST 不被保存為正常資料，來源診斷與關注更新基準 MUST 可重新讀取最新狀態。顯示舊快照時 MUST 不以伺服器較新 token 將使用者未讀內容標已讀。

#### Scenario: 更新後重新取得
- **WHEN** 匯入研究或新增觀測後，使用者重新取得資料
- **THEN** 可讀到新提交的內容；其他讀者在約定的新鮮度內取得更新
- **AND** 關注的已讀基準仍對應使用者實際看到的回應

#### Scenario: 請求失敗後重試
- **WHEN** 來源狀態或 API 請求曾失敗後恢復
- **THEN** 重試可取得恢復狀態，不被快取的錯誤或其他查詢資料遮蔽

### Requirement: 小群讀取效能以可重現基準驗收

系統 MUST 在記錄的本機隔離環境及固定資料快照，以 10 位同時讀取者、暖機及固定查詢分布量測改善前後結果。驗收目標 MUST 為暖機後每個常用 API 的 p95 < 500ms、覆蓋摘要 p95 < 1 秒且無非預期錯誤；MUST 公開測試條件、樣本數、冷讀結果及限制，未達標不得宣稱容量已保證。

#### Scenario: 相同環境比較改善前後
- **WHEN** 執行讀取效能驗收
- **THEN** 記錄硬體、服務設定、資料筆數、各 endpoint 分布與延遲、錯誤及快取狀態
- **AND** 包含從網站同網域 API 到 backend 的路徑，不只量測前端記憶體命中

#### Scenario: 測量未達目標
- **WHEN** 任一常用 endpoint 的 p95 未達目標或有非預期錯誤
- **THEN** 記錄瓶頸與未通過結果，繼續修正既有讀取流程或明列尚未完成
- **AND** 不以其他 endpoint 的平均值、降低併發或增加未授權基礎設施掩蓋

### Requirement: 文件更新隔離且重啟不製造更新

新增文件投影與監測 MUST 以 additive 方式保留原研究、事件、財報、觀測、判讀版本及此裝置關注契約。監測 MUST 與公開讀取隔離，遵守現有排程防重疊規則。來源部分失敗、重跑、API／worker／DB 重啟 MUST 不製造假文件版本、研究版本或更新提示。

#### Scenario: 部分失敗後重跑並重啟
- **WHEN** 一個文件來源失敗、另一個成功，隨後重跑並重啟服務
- **THEN** 已成功內容、原研究與歷史保持可讀，相同內容不重複建立候選或版本
- **AND** 每個來源保留各自操作狀態，公開 API 不直接呼叫外部文件來源
