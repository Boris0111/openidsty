# Spec Delta

## ADDED Requirements

### Requirement: 技術研究覆蓋與文件待核對獨立呈現

覆蓋 API 與可保存維護報告 MUST 對所有目前環節及題材列出技術研究面向是否整理、可回溯論述及文件、已核對版本／日期、待核對更新與具體缺口。技術文件數、來源設定數、新聞量或代理指標有值 MUST NOT 被當成研究完整或論述已核實；沒有技術證據的面向 MUST 可明示尚待補強。

#### Scenario: 有新聞但缺少替代限制證據
- **WHEN** 某環節已有近期直接事件而替代條件尚無可核對文件
- **THEN** 事件數照實呈現，技術研究面向保留缺口，不因有新聞而標為完成

#### Scenario: 原研究引用舊版文件
- **WHEN** 文件監測發現尚未核對的新版本
- **THEN** 維護報告同時保存既有已核對基準與待核對候選；一般覆蓋頁不展示維護佇列，不將研究查核日期改成取得日

### Requirement: 技術來源故障不遮蔽既有研究與報告

覆蓋 API 與可保存維護報告 MUST 在技術來源失效、版本未知或尚無全文時仍提供既有研究、必要摘錄、來源限制及缺口。既有 30／90 日直接事件、背景、未知日期、公司提及、指標與判讀計數 MUST 維持原定義；技術文件觀測 MUST 分開呈現。

#### Scenario: 文件 403 但研究已核對
- **WHEN** 已引用的文件目前回應 403
- **THEN** 報告保留查核日、版本與研究，另列目前取得失敗及最後成功
- **AND** 不把研究列為不存在，不把文件觀測補算成直接新聞

### Requirement: 全圖閱讀與缺口驗收可逐列追溯

交付 MUST 提供涵蓋目前 17 個環節及 7 個題材的可保存驗收矩陣，逐列記錄閱讀入口、技術面向、證據與適用範圍、來源限制、未解缺口及實際查核結果。矩陣 MUST 來自當次資料與走查，離線 fixtures 與真實取得紀錄 MUST 可區分；來源不足可保留明確缺口，不得以示範值補齊。

#### Scenario: 完成全圖走查
- **WHEN** 維護者依矩陣查閱全部環節與題材
- **THEN** 每列可回到對應研究與證據，並分辨已核對內容、條件推論及仍待核實事項
- **AND** 初版與來源失效情境均可閱讀，不將測試樣本宣稱為真實覆蓋
