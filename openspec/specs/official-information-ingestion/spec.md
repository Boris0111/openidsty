# official-information-ingestion Specification

## Purpose

將免費官方公告、法說資料與基本財報整理為具來源及時間的事件資料，維持公司識別、財報口徑、更新健康狀態與重跑一致性，確保後續圖形與摘要有可驗證的資訊基礎。

## Requirements

### Requirement: 官方資訊可追溯

系統 MUST 介接免費官方資料、產業媒體及背景統計；每個事件 MUST 保留來源識別、URL、原始資料與取得時間。發布日、出表日、活動日 MUST 分開，未知發布日 MUST 保留空值，日期精度為日時 MUST 不顯示午夜。沒有單一公司事件 MUST 允許空 ticker；只有外殼或無內容 MUST 視為失敗。

#### Scenario: 官方資料與外殼頁面
- **WHEN** 來源回傳可解析公告
- **THEN** 建立可點回來源的事件
- **AND** 若只回 JavaScript 外殼，來源狀態顯示未成功，既有資料仍保留

#### Scenario: 出表日與活動日期
- **WHEN** 台灣財報只有出表日期或 IR 只有活動日期
- **THEN** 不將該日期宣稱為真正發布日，取得時間另行保留

### Requirement: 重跑一致與來源隔離

同一來源文件重跑 MUST 不重複建立事件與財報；同一提供者的跨 feed 文章 MUST 以 canonical URL 去重，統計報告 MUST 依資料集與期別識別。某來源失敗 MUST 不阻止其他來源成功，並保留最後嘗試、最後成功、錯誤原因及新增筆數。不同提供者未確認同一事件時不得僅憑標題合併。

#### Scenario: 部分來源失敗後重試
- **WHEN** 一來源逾時而其他來源成功，下一輪重跑
- **THEN** 保留失敗狀態並只加入尚未存在的資料

#### Scenario: 跨 feed 與統計修訂
- **WHEN** 同一科技新報文章出現在兩個 feed，或同一期報告更新
- **THEN** 不建立重複事件，保留來源與期別

### Requirement: 公司對應保守且支援中文

系統 MUST 以發行公司或官方識別欄位決定事件主體，並支援中文別名與英文 token 邊界。正文提及公司 MUST 與主體、圖形推導公司分開，不得依 tier 將被提及的大廠升格為主體。

#### Scenario: 中文與英文名稱比對
- **WHEN** 文字出現台積電、臺積電、NVIDIA 或 AMD
- **THEN** 可對應正確 ticker
- **AND** AMD 不得因出現在較長英文單字內而誤命中

### Requirement: 來源檢查與離線測試

系統 MUST 提供維護者單次擷取及來源健康查詢；測試 MUST 可用離線 fixtures 驗證解析、去重、財報口徑與失敗行為。讀者不得取得測試 fixtures、擷取診斷或維護設定。外部來源失效時 MUST 保留已發布研究與最後有效數值，在數值旁標實際期間及必要缺口，詳細失敗狀態只供管理介面查詢。

#### Scenario: 未取得資料
- **WHEN** 所有外部來源暫時失效
- **THEN** 網站仍顯示地圖與既有內容，讀者可識別資料時點與缺口，維護者可查來源失敗原因

### Requirement: 全範圍內容分類與影響起點

系統 MUST 為全部環節及題材建立中英文規則，保留命中詞、摘錄及版本。直接相關、背景統計與公司提及 MUST 分開；例行財報與軟體誤命中 MUST 排除直接分類，首頁 MUST 優先產業變化。影響推導 MUST 從直接內容分類開始，不得以公司的全部角色取代內容起點。

#### Scenario: 只有公司名稱
- **WHEN** 文章提及台積電但沒有產業技術內容，或 AMD 出現於 AMDOCS
- **THEN** 不因此建立直接環節事件；英文名稱遵守 token 邊界

#### Scenario: 真實分類與排除
- **WHEN** 離線驗證真實文章
- **THEN** 全部環節與題材有正例，並測試誤命中、中文別名、英文邊界與例行財報／軟體排除

### Requirement: 指標自動更新與重跑隔離

免費公開指標來源 MUST 接入既有每小時更新及防重疊機制；重跑 MUST 依指標、資料集／對象、期別及口徑去重並保留真實修訂。某指標來源失敗 MUST 不阻止其他來源、事件或既有財報成功；既有來源識別及歷史資料 MUST 保留，數值更新不得自動改寫研究判讀。

#### Scenario: 指標解析失敗但新聞成功
- **WHEN** 官方數值格式變動而其他新聞來源可解析
- **THEN** 指標來源顯示失敗與原因，新聞照常保存，舊觀測與查核判讀仍可閱讀

### Requirement: 數值擷取有明確標籤及範圍

指標擷取 MUST 以官方欄位或可辨識段落標籤確認數值、資料期間、單位及衡量對象，保留來源與必要原始依據；無法區分混合業務或預估值時 MUST 不當成已實現題材數值。HTTP 成功但缺乏可解析數值 MUST 如實反映資料缺口，測試樣本不得進入正式資料流程。

#### Scenario: 液冷與混合業務揭露
- **WHEN** 來源同時提及 BASX 混合收入及明確區分的液冷產品收入
- **THEN** 只將可辨識液冷欄位投影到液冷收入指標，混合口徑不冒充該數值

#### Scenario: 製程營收占比與指引
- **WHEN** 官方財報列出當季 2nm 晶圓營收占比及未來量產計畫
- **THEN** 觀測使用當季已實現比例與期間，未來計畫仍是待確認資訊

### Requirement: 財務觀測可重現且不跨申報混用

自動與人工核對匯入的財務 MUST 保存官方識別、原始數值與單位、期間、申報範圍、來源文件及修訂依據。不同申報、公司、幣別或會計範圍不得拼接成一筆報表；自訂或無法確認的欄位映射 MUST 保留待核對，不自行映射。有效值修訂追加歷史，相同內容重跑不新增修訂。

#### Scenario: 同期存在原申報與修正版
- **WHEN** 後續抓取取得同一報表期間的修正版
- **THEN** 新版與原版可追溯，預設值來自最新有效申報，同一筆資料再抓取不新增版本

### Requirement: 來源能力限制與官方補錄

台美財務 MUST 優先使用免費官方資料，逐來源標明可取指標、頻率與歷史限制。未提供的現金流、資本支出、現金或其他市場數值 MUST 可由維護者附官方文件及定位核對補錄；來源無法取得時保留缺口，不用公司總營收、資產變動或估算替代所需指標。

#### Scenario: 台灣摘要沒有營業現金流
- **WHEN** 已取得損益與負債摘要，但該來源未提供現金流
- **THEN** 可顯示已取得指標，其餘標為未取得，核對官方財報後才能補錄對應數值

### Requirement: 來源分類不得自動提升研究確定性

事件 MUST 區分官方發布、具名報導及傳聞觀察，並保留來源、時間、主體與內容提及的差異。自動擷取與內容分類只增加事件或候選資訊，不得直接改寫已發布客戶、供應、商業化或技術主張；傳聞變為正式研究 MUST 經研究發布流程。

#### Scenario: 取得匿名供應鏈消息
- **WHEN** 來源包含未經證實的供應客戶傳聞
- **THEN** 只建立有來源的觀察資訊，不改寫正式供應關係

### Requirement: 更新節奏有界且部分失敗隔離

系統 MUST 每小時檢查到期來源，公告預設每小時、財務／月營收預設每日更新，並支援維護者單次更新。請求 MUST 遵守提供者限流；逾時、429、403 或格式改變時不得阻塞其他來源或刪除有效資料。主機停機後 MUST 可補跑到期任務，不宣稱停機期間持續更新。

#### Scenario: SEC 暫時限流
- **WHEN** SEC 回傳 429 而台灣來源可正常讀取
- **THEN** SEC 依限流資訊延後重試，其他來源完成，既有 SEC 數值仍可閱讀
