# platform-runtime Specification

## Purpose

提供可重現的本機開發及自架執行環境，讓產業資訊網站、資料庫與每小時資料流程能一致初始化、持續更新、保留資料並透過操作文件維護，而不影響同機其他專案。

## Requirements

### Requirement: 可重現啟動與持久化

系統 MUST 提供容器設定、環境變數範例、資料庫遷移與研究初始化；停止／重啟 MUST 保留資料。讀者 API MUST 維持唯讀語意，管理寫入 MUST 使用獨立授權邊界；資料庫、Git 編輯空間與流程管理介面預設只在本機或內部可達。本版供本機及私人網路使用，讀者入口不得轉送管理路徑。

#### Scenario: 新環境與重啟
- **WHEN** 維護者依 README 啟動並重啟服務
- **THEN** 可開啟產業圖，資料庫保留既有事件，其他專案服務不受影響

### Requirement: 每小時排程獨立執行

資料流程 MUST 每小時嘗試更新，並獨立於公開 API worker 運作。重啟或重複觸發 MUST 不造成重複入庫；同一輪任務不得併發執行。

#### Scenario: API 重啟與排程
- **WHEN** API 服務重啟或增加 worker
- **THEN** 不額外建立排程，資料流程可繼續運作

### Requirement: 開發與維護操作可驗證

README MUST 提供前後端開發、容器啟動與停止、單次資料更新、測試、日誌、來源狀態、備份還原及公開部署步驟；專案 MUST 提供 dev server 啟動設定。

#### Scenario: 執行單次更新與備份
- **WHEN** 維護者依文件執行更新、備份與還原
- **THEN** 能查詢更新結果，且在獨立還原環境核對資料，不覆寫其他專案

### Requirement: 版本控制內容可完整重現公開入口

專案 MUST 僅憑版本控制的乾淨 checkout 與文件中的本機設定重現公開入口；忽略規則不得排除必要應用原始碼。自動檢查 MUST 驗證地圖、後端離線測試、前端型別／建置及主要導覽，與真實外部來源擷取分開；正式 runtime 不得載入測試 fixtures。

#### Scenario: 資料覆蓋頁與產物同名
- **WHEN** 乾淨 checkout 建置網站並開啟資料覆蓋入口
- **THEN** 該頁原始碼在版本控制中，入口可載入，測試 coverage 產物仍可忽略

### Requirement: 來源配置與恢復結果可驗證

維護文件 MUST 提供 SEC 真實聯絡設定、官方來源失敗分類、單來源重試及結果核對方法。缺少配置與 HTTP／解析失敗 MUST 分開顯示；無法恢復的來源 MUST 保留既有資料及實際限制。配置與恢復不得重置其他服務或以外殼回應宣稱成功。

#### Scenario: SEC 尚未設定且官方 IR 持續封鎖
- **WHEN** 維護者檢查未配置的 SEC 與回傳 HTTP 403 的 IR
- **THEN** 可辨識各自處理方式，重試仍失敗時留下來源限制，其他來源及研究仍可使用

### Requirement: 一般讀取有界且保留既有資料語意

常用 API MUST 只回傳請求所需的分頁或樣本，總數與筆數限制 MUST 在取得結果前生效；結果 MUST 保持原分類、日期、期別、修訂與排序定義。覆蓋摘要 MUST 不因加入較舊歷史就返回全部原始事件或觀測。效能最佳化 MUST 不截斷影響候選、隱藏未知日期或把缺少資料變成零。

#### Scenario: 增加歷史觀測與事件
- **WHEN** 資料庫累積更多舊事件及指標修訂
- **THEN** 摘要維持有界回應，分頁總數及最新有效修訂正確
- **AND** 同一資料快照上的 30／90 日計數、直接分類與既有樣本定義不變

### Requirement: 快取可重新取得且新鮮度有界

快取 MUST 依資源、研究版本及完整查詢參數隔離，並依資料性質區分：manifest 與未指定研究版本的查詢 MUST 取得目前已發布版本，不保存成功快取；指定已發布版本的研究、目錄、圖與固定引用內容不可變，可長期快取，新版本使用不同 key；財務、事件、觀察及含財務的比較即使指定研究版本仍屬動態資料，快取 MUST 不超過 60 秒；覆蓋、來源狀態與收藏更新查詢 MUST 可重新取得，管理及身分回應 MUST NOT 進入共用快取。新鮮度上限指相對系統已入庫或已發布資料的讀取延遲，不代表官方來源發布後即在該時間內更新。

重新取得 MUST 可略過快取；失敗回應 MUST 不被保存為正常資料。背景頁、斷線或更新失敗時 MAY 保留最後成功內容並提示；閱讀中發現新研究版本 MUST 先通知，由讀者決定切換。顯示舊快照時 MUST 不以伺服器較新 token 將使用者未讀內容標已讀。

#### Scenario: 更新後重新取得
- **WHEN** 發布新研究版本或新增觀測後，讀者重新取得資料
- **THEN** 未指定版本的查詢取得新版本；已固定舊版的頁面先提示，接受後才整頁切換
- **AND** 動態數值在約定新鮮度內反映已入庫資料，收藏已讀基準仍對應實際看到的回應

#### Scenario: 請求失敗後重試
- **WHEN** 來源狀態或 API 請求曾失敗後恢復
- **THEN** 重試可取得恢復狀態，不被快取的錯誤或其他查詢資料遮蔽

### Requirement: 小群讀取效能以可重現基準驗收

系統 MUST 在記錄的本機隔離環境，以固定的真實資料快照及擴大測試資料兩組、10 位同時讀取者、暖機及固定查詢分布量測，並同時運行到期資料更新。驗收目標 MUST 為暖機後每個常用 API 的 p95 < 500ms、覆蓋摘要 p95 < 1 秒且無非預期錯誤；MUST 公開硬體、服務設定、資料規模、各 endpoint 樣本數與延遲、冷讀結果、錯誤、快取狀態及限制。測試資料 MUST NOT 寫入正式資料庫或冒充正式研究；未量測或未達標時不得宣稱容量已保證，快取或其他功能完成不代表效能目標已達成。

#### Scenario: 相同環境比較改善前後
- **WHEN** 在兩組資料上執行固定工作負載並同時運行到期更新
- **THEN** 記錄各 endpoint 分布與延遲、錯誤及快取狀態，可與同環境先前基準比較
- **AND** 包含從網站同網域 proxy 到 backend 的路徑，不只量測前端記憶體命中

#### Scenario: 測量未達目標
- **WHEN** 任一常用 endpoint 的 p95 未達目標或有非預期錯誤
- **THEN** 記錄瓶頸與未通過結果，繼續修正既有讀取流程或明列尚未完成
- **AND** 不以其他 endpoint 的平均值、降低併發或增加未授權基礎設施掩蓋

### Requirement: 文件更新隔離且重啟不製造更新

新增文件投影與監測 MUST 以 additive 方式保留原研究、事件、財報、觀測、判讀版本及此裝置關注契約。監測 MUST 與公開讀取隔離，遵守現有排程防重疊規則。來源部分失敗、重跑、API／worker／DB 重啟 MUST 不製造假文件版本、研究版本或更新提示。

#### Scenario: 部分失敗後重跑並重啟
- **WHEN** 一個文件來源失敗、另一個成功，隨後重跑並重啟服務
- **THEN** 已成功內容、原研究與歷史保持可讀，相同內容不重複建立候選或版本
- **AND** 每個來源保留各自操作狀態，公開 API 不直接呼叫外部文件來源

### Requirement: 新舊開發環境相互隔離

新版預覽 MUST 使用獨立程式工作目錄、容器 project、image、network、資料庫、volumes、ports 與執行憑證，不可覆寫既有服務。操作前 MUST 確認目標範圍與 port；還原／遷移只在明確指定的新版資料庫執行。Git 分支回退不得被視為已還原資料庫。

#### Scenario: 預覽新版並保留原服務
- **WHEN** 啟動、重建或停止新版預覽環境
- **THEN** 原服務的容器、image、資料與連線保持原狀

### Requirement: 版本化讀取與有界請求

新版讀取介面 MUST 與 legacy 契約並存，研究回應可固定已發布版本，動態數據標示資料時點。清單與圖形查詢 MUST 有數量及深度界線，回應截斷需明示；相同請求可合併，管理及身分回應不得共用快取。發布或還原後不得混用不同研究版本的內容。

#### Scenario: 大型關係查詢
- **WHEN** 查詢關係數超過單次限制
- **THEN** 回應明示截斷並提供繼續探索方式，請求不無限遍歷或耗盡資源

### Requirement: 故障可恢復且不偽裝新鮮度

來源失敗 MUST 保留最後有效資料，發布失敗 MUST 保留舊研究；資料庫不可用時 MUST 回傳可重試的服務不可用狀態，不假造空資料成功。系統 MUST 定期備份資料庫、研究 Git 歷史與資產，並能在獨立環境核對還原；祕密設定不得隨公開研究或收藏備份流出。

#### Scenario: 資料庫故障
- **WHEN** 讀取 API 無法連線資料庫
- **THEN** 回傳服務不可用及請求識別，畫面保留已成功載入的內容並說明目前無法更新

#### Scenario: 隔離還原演練
- **WHEN** 維護者從備份建立新的還原環境
- **THEN** 能核對正式研究版本、歷史、數值修訂與資產，不覆寫原資料庫
