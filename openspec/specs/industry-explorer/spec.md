# industry-explorer Specification

## Purpose

提供公開的半導體與 AI 伺服器產業鏈導覽，讓使用者從完整環節圖取得環節定位、代表公司與來源資訊，再比較公司或沿事件的可解釋路徑深入研究。

## Requirements

### Requirement: 完整產業圖與環節導覽

系統 MUST 顯示所選產業的全部環節，並支援由應用、供應角色／子領域、產品與技術探索公司；跨產業鄰接環節預設收合且可展開。點選節點 MUST 同步顯示定位、角色、產品、條件、風險、研究與直接事件入口；選取環節 MUST 列出該環節的供應鏈並可進入供應鏈頁。供應、能力、合作與需求回饋連線 MUST 可辨識並保留回路。圖與文字清單 MUST 皆能完成導覽，查詢截斷不得偽裝成全圖。

#### Scenario: 開啟並選擇環節
- **WHEN** 使用者開啟產業圖並點選散熱
- **THEN** 可直接閱讀研究、高亮選中及相鄰環節、連線，並跳轉題材與公司頁
- **AND** 可縮放、平移及重設圖形，亦可從文字清單選取環節
- **AND** 可看到散熱下的供應鏈並進入 AI 機櫃液冷

#### Scenario: 由產品找到公司並讀取關係
- **WHEN** 讀者由液冷展開冷板並選取公司與產品的連線
- **THEN** 可查看具體交付內容、適用條件及來源，供應能力不被畫成已確認客戶交易

### Requirement: 可解釋且可終止的事件影響路徑

系統 MUST 提供上下游、題材橫向及共同下游手足三種遍歷，記錄已訪問節點並保留路徑種類；結構推導 MUST 標示為 inference，不得宣稱相關公司必然受惠。介面 MUST 將完整結構候選與有來源、機制及條件的傳導假設分開，預設收合完整候選並可展開，不將候選數量當成影響程度或證據強度。

#### Scenario: 液冷事件與圖中回路
- **WHEN** 由散熱事件查詢影響範圍
- **THEN** 可透過題材找到電源、透過共同下游找到 PCB
- **AND** 遇到資料中心與運算的回路仍可終止

#### Scenario: 候選擴散到大部分產業
- **WHEN** 一則事件的結構遍歷取得大量環節與公司
- **THEN** 先顯示可展開的候選範圍說明，不將整份候選清單展示為已核實受惠結論

### Requirement: 選取一致性與可分享導覽

系統 MUST 將產業、物件與篩選選取記錄於 URL，支援返回與分享；快速點選不得顯示上一物件資料，resize MUST 保留縮放與平移。搜尋 MUST 支援環節、題材、公司中文／英文別名、上市代號、產品與術語，以及鍵盤操作；歧義 MUST 顯示候選，不得靜默合併不同公司。既有地圖、題材、事件與新版研究頁 MUST 共用同一頁首、搜尋與依分類產生的麵包屑，跨頁移動不需回到另一個網站首頁才能繼續。

#### Scenario: 快速切換與返回
- **WHEN** 使用者快速連點不同環節再按返回
- **THEN** 內容與 URL 選取一致，較慢回應不覆蓋當前內容

#### Scenario: 由地圖讀到公司再逐層返回
- **WHEN** 讀者由產業地圖選散熱，進入 AI 機櫃液冷，選冷板後開啟雙鴻
- **THEN** 每頁都有同一頁首與麵包屑，可由麵包屑或返回回到上一層，不需重新尋找入口

#### Scenario: 中文別名與英文邊界
- **WHEN** 搜尋臺積電、台積電、2330.TW、NVIDIA 或 AMD
- **THEN** 可找到正確公司，AMD 不因出現在 AMDOCS 中而被誤認為同一主體

### Requirement: 題材研究與手機閱讀

每個題材 MUST 有獨立頁面，優先顯示有條件判讀、支持／反向證據及缺口，再提供實際指標、商業化核對、全文、查核日、相關環節及事件；預期里程碑 MUST 與已發生事件分開。判讀版本比較與收藏入口 MUST 可鍵盤操作。手機 MUST 預設可讀清單與選中環節局部圖，可開全螢幕完整圖，點選後立即閱讀內容。

#### Scenario: 液冷題材與手機導覽
- **WHEN** 使用者在手機以鍵盤選散熱再開液冷
- **THEN** 可閱讀完整研究及查核基準，預期里程碑不被展示為已發生新聞

#### Scenario: 判讀與資料更新不同步
- **WHEN** 使用者在手機查閱查核基準之後有新指標或公開事件的題材
- **THEN** 可分辨原查核判讀、新數值與事件的資料時點，並能開啟版本比較或加入此裝置收藏
- **AND** 不顯示待納入判讀的維護佇列

### Requirement: 一般閱讀使用中文名稱與一致證據程度

一般閱讀的環節、題材、來源、狀態與判讀 MUST 優先使用可理解的中文名稱。`well-supported`、`inference`、`needs-verification` MUST 統一呈現「有明確證據支持／有條件推論／仍待核實」。一般閱讀 MUST NOT 顯示內部識別碼、原始列舉與診斷的通用展開區；原值保留在唯讀 API 及維護流程；公司 ticker、正式技術名稱與原文證據可保留。來源故障 MUST 提供中文說明及重試方式。

#### Scenario: 閱讀題材及來源限制
- **WHEN** 使用者開啟題材、環節或來源頁
- **THEN** 導覽、路徑及支持程度顯示中文名稱，原始代碼與錯誤不擠入主要研究
- **AND** 畫面不另列「進階資訊」，來源失敗仍保留原判讀及重試方式

#### Scenario: 名稱尚未提供
- **WHEN** 回應包含尚無中文對照的識別或狀態
- **THEN** 顯示可理解的資料待補說明，原值保留在 API，不顯示成空白或誤配其他名稱

### Requirement: 數值易讀且保留衡量口徑

指標及版本差異的數值 MUST 保留單位、幣別、期別與範圍，以適當尺度顯示大數值且可查精確原值；四捨五入 MUST 不影響比較運算。百分比與百分點 MUST 分開，零值、負值及未知值 MUST 可辨認，MUST NOT 自動換幣或把公司整體營收標成題材收入。

#### Scenario: 大額營收與比例比較
- **WHEN** 查看大額營收、比例或其修訂差異
- **THEN** 顯示易讀單位、原幣別與期別，精確原值可從數值提示／無障礙名稱及修訂明細核對
- **AND** 比例差以百分點呈現；不符合口徑時保留不可比較原因

#### Scenario: 零值與未知值
- **WHEN** 觀測為零、負值或未取得
- **THEN** 零與負值正常顯示，未取得仍顯示缺口，不被格式化成零

### Requirement: 供應與需求回饋可區分並閱讀連線依據

產業圖及等價文字清單 MUST 區分供應關係與需求回饋，使用文字及線型輔助且不僅依顏色。選取連線 MUST 可閱讀中文起訖、關係方向、供應項目或需求機制、介面依賴、成立條件、證據與缺口。未知資訊 MUST 明示待核實，結構存在 MUST NOT 被呈現為已確認公司交易。

#### Scenario: 查看資料中心回饋運算需求
- **WHEN** 使用者選取資料中心指向運算晶片的連線
- **THEN** 可辨識為需求回饋並閱讀需求形成條件，不將其解釋為資料中心供應晶片
- **AND** 原有回路與上下游、題材、共同下游手足遍歷結果仍保留

#### Scenario: 閱讀供應連線
- **WHEN** 使用者選取散熱至系統組裝的關係
- **THEN** 可閱讀供應產品、整合介面及驗證條件，證據不足的客戶或料號留為缺口

### Requirement: 連線選取支援分享返回與鍵盤

連線選取 MUST 與產業／環節狀態共同保存在 URL，支援直接開啟、返回及清除選取；既有環節 URL MUST 仍有效。手機與鍵盤 MUST 可透過文字清單選取同一關係、閱讀詳情及返回原焦點。快速切換 MUST 不顯示前一連線內容，一般 resize MUST 保留圖形縮放及平移。

#### Scenario: 分享及快速返回
- **WHEN** 使用者開啟分享連線後快速切換另一關係並返回
- **THEN** URL、選取樣式與詳情一致，較慢回應不覆蓋當前選取

#### Scenario: 手機鍵盤操作
- **WHEN** 使用者只用鍵盤由關係清單開啟詳情再關閉
- **THEN** 可閱讀與圖相同資訊並回到原項目，不需精確點擊畫布連線

### Requirement: 初次閱讀與歷史載入相互獨立

同一頁面同時需要相同資料時 MUST 合併讀取並共享結果；初次題材閱讀 MUST 不取得未開啟的歷史列表或版本比較。展開歷史或分享指定比較時 MUST 取得相應內容。元件卸載、快速切換及局部失敗 MUST 不取消其他讀者仍需要的請求，也不得以舊題材回應覆蓋當前題材。

#### Scenario: 初次閱讀後展開歷史
- **WHEN** 使用者開啟題材頁再主動展開版本比較
- **THEN** 初次只取得閱讀所需資料，歷史及差異於需要時載入
- **AND** 同一資源的併發使用者共用請求，局部失敗可獨立重試

#### Scenario: 直接開啟版本比較連結
- **WHEN** 分享連結指定比較版本
- **THEN** 自動展開並載入指定比較，保留回到目前判讀的操作

### Requirement: 閱讀按研究任務分組且不展示維護佇列

環節 MUST 先呈現定義，並以產業角色、技術與限制、追蹤重點分組閱讀；題材 MUST 先呈現研究判讀，並可切換技術與供應鏈、數據與追蹤。不同任務的長篇內容 MUST NOT 同時堆疊；里程碑計畫與核對 MUST 合併。分組 MUST 支援鍵盤及既有分享深連結。一般研究與覆蓋頁 MUST NOT 出現「技術文件與待核對」、文件或事件候選佇列、候選數或觀測歷史；引用 MUST 跟隨論述提供章節、摘錄及適用範圍。舊 `#candidates` 分享連結 MUST 轉到題材的數據與追蹤並說明待核對資訊已移至維護端，不重新展示候選佇列。搜尋歧義候選、比較候選公司及影響遍歷的結構候選屬讀者功能，不受此限制。

#### Scenario: 先理解散熱的供應角色再核對技術
- **WHEN** 讀者開啟散熱環節
- **THEN** 預設可讀定義、供需與傳導及代表公司，不被技術欄位或文件監測清單擠到頁尾
- **AND** 可用鍵盤切到技術與限制，開啟論述引用後閱讀指定版本章節與摘錄，不展示原始識別碼

#### Scenario: 分享指標與回看判讀
- **WHEN** 開啟題材 #indicators 分享網址
- **THEN** 自動選取數據與追蹤，目標內容可讀
- **AND** 可切回研究判讀，來源或指標失敗不遮蔽已保存研究

#### Scenario: 開啟舊的候選資訊連結
- **WHEN** 開啟題材 #candidates 舊分享網址
- **THEN** 轉到數據與追蹤並以一句話說明待核對資訊已移至維護端，可閱讀公開事件與指標
- **AND** 不顯示候選清單、候選數或處理狀態

### Requirement: 依研究任務呈現且維護資訊隔離

新版一般閱讀 MUST 優先顯示中文名稱、產品角色、商業意義、圖解、條件及相關來源，提供易讀數值並保留原幣與期間。內部 ID、原始 JSON、來源設定、待核對佇列、parser 診斷及維護統計 MUST 留在管理介面；不得以「進階資訊」抽屜重新加入一般閱讀。研究缺口僅在影響該主張時精簡說明。

#### Scenario: 一般讀者檢閱公司與題材
- **WHEN** 讀者開啟公司產品定位或題材判讀
- **THEN** 可直接查證論點旁的來源與適用範圍，不需閱讀維護狀態或工程欄位

### Requirement: 傳聞觀察與正式研究分開

傳聞 MUST 有獨立觀察入口、來源、時間與未證實說明，預設不加入正式供應關係圖或已發布研究主張。媒體報導、官方發布與研究推論 MUST 可分辨；重複轉載或消息數量不得提升確定性，轉為正式主張必須經維護者查核及研究發布。

#### Scenario: 多家媒體轉載同一匿名客戶消息
- **WHEN** 傳聞出現多次但沒有新增可核實證據
- **THEN** 觀察內容可見來源，正式圖及公司客戶主張維持原狀

### Requirement: 跨版本閱讀一致且可回到原研究

同一研究頁面的地圖、公司、產品、主張及引用 MUST 來自同一已發布研究版本；動態事件與指標 MUST 另標資料時點。閱讀期間有新發布時 MUST 保留當前內容，讓讀者選擇載入新版；歷史比較按需讀取，來源失效不得刪除已發布研究。

#### Scenario: 閱讀時發生發布
- **WHEN** 讀者尚在舊版公司頁，背景已發布新版產品分類
- **THEN** 當前頁不混入新版關係或引用，接受更新後整頁一致切換

### Requirement: 供應鏈頁一致呈現

每個應用 MUST 有供應鏈頁，以同一版型呈現問題式標題、圖解（無圖解時為文字步驟）、依步驟排列的產品與有產品證據的公司、缺口及研究內容；不得只為單一供應鏈提供專屬入口或版型。只有供應鏈頁顯示完整圖解；產品與角色頁 MUST 顯示所在供應鏈的步驟位置並可回到供應鏈頁；公司研究 MUST 為獨立頁面，列出所屬供應鏈與產品，不嵌在圖解內。缺少證據的產品 MUST 明示缺口，不以空白或其他供應鏈的內容補位。

#### Scenario: 開啟沒有圖解的供應鏈
- **WHEN** 讀者開啟晶圓製造
- **THEN** 以相同版型顯示文字步驟、產品與缺口

#### Scenario: 在手機從產品頁回到供應鏈
- **WHEN** 讀者在手機開啟冷板
- **THEN** 第一屏即為冷板內容，頂端位置列標示冷板在 AI 機櫃液冷的步驟，並可回到完整圖解

#### Scenario: 公司跨多條供應鏈
- **WHEN** 讀者開啟日月光投控
- **THEN** 公司頁獨立呈現研究與近期事件，並列出封裝與測試兩條供應鏈

### Requirement: 閱讀頁在手機寬度與縮放時不水平溢出

產業地圖與研究閱讀頁在 390px 以上的視窗寬度 MUST 不產生水平溢出，頁面寬度不得超過視窗寬度。視窗由寬變窄（例如手機轉向、桌機縮放視窗）的過程中，關係圖等依前一個尺寸繪製的元件 MUST 不撐寬頁面，在重新繪製前也不得出現水平捲動。關係圖既有的縮放比例、平移與互動 MUST 不因此改變。

#### Scenario: 由桌機寬度縮到手機寬度
- **WHEN** 讀者在 1440px 寬開啟有關係圖的研究頁，接著把視窗縮到 390px
- **THEN** 縮窄的當下與之後，頁面都不出現水平捲動；關係圖在新寬度內重新繪製

#### Scenario: 縮放後保留關係圖狀態
- **WHEN** 讀者先放大關係圖，再把視窗放寬又縮回手機寬度
- **THEN** 關係圖保留原縮放比例，頁面沒有水平溢出

#### Scenario: 直接以手機寬度開啟
- **WHEN** 讀者以 390px 寬直接開啟產業地圖或研究頁
- **THEN** 頁面寬度不超過視窗寬度
