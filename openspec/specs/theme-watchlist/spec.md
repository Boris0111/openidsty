# theme-watchlist Specification

## Purpose

讓使用者在同一裝置保存關注題材與已讀基準，集中查看判讀變更、實際指標更新及待納入判讀的新資訊，並清楚區分研究結論的改變與單純資料取得。

## Requirements

### Requirement: 此裝置的關注清單

使用者 MUST 能在題材列表或詳情加入／移除關注，並在重新整理後保留同裝置的清單。儲存不可用、內容損壞或題材已不存在 MUST 提供精簡提示並保留其他可用題材；不要求登入，不宣稱已跨裝置同步。

#### Scenario: 重新整理與無效儲存
- **WHEN** 使用者重新整理關注頁，或瀏覽器中的儲存內容損壞
- **THEN** 有效清單可恢復；損壞資料不阻止公開研究閱讀，儲存限制可辨識

### Requirement: 更新種類分開呈現

關注頁 MUST 分開呈現判讀版本變更、指標新期／修訂及未納入判讀的候選資訊。相同內容的重跑、取得時間刷新或來源錯誤 MUST NOT 產生假的判讀／指標更新；新收錄但發布日未知的資訊不得稱為新發生的產業事件。

#### Scenario: 每小時重跑沒有新內容
- **WHEN** 來源再次成功但判讀與觀測內容未變
- **THEN** 不新增未讀判讀或指標提示，來源健康仍可個別查詢

### Requirement: 已讀基準對應實際顯示內容

首次加入關注 MUST 以當時可見的判讀版本與指標更新標記建立基準。使用者 MUST 能明確將當前顯示的更新標為已讀；標為已讀不得將尚未載入或更新之後的內容提前視為已讀。移除關注 MUST 一併移除該題材的本機已讀基準。

#### Scenario: 讀取途中出現新版本
- **WHEN** 使用者查看舊回應並標為已讀，而伺服器已有較新判讀
- **THEN** 只記錄已顯示版本，下一次刷新仍能看見較新更新

### Requirement: 公開更新摘要不保存個人名單

公開更新查詢 MUST 為所指定題材提供當前判讀版本、指標內容更新標記與候選資訊摘要，維持唯讀；個人關注及已讀紀錄 MUST 保存在裝置。不存在的題材 MUST 可逐項辨識，不阻止其他題材取得結果。

#### Scenario: 關注清單含已移除題材
- **WHEN** 清單同時包含有效與不存在的題材
- **THEN** 有效題材仍可查看，無效項目提示已不可用並可移除
