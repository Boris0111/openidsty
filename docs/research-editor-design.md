# 草稿編輯與預覽的閱讀設計

沿用 Boris 已接受的新版研究視覺，不重做一般讀者版面。管理入口 `/admin` 只提供維護者登入、草稿選擇、欄位／Markdown 編輯、差異、驗證及預覽；發布／來源健康由後續 task 4.6 補齊。

色彩沿用白色 `#ffffff`、背景 `#f6f8f8`、正文 `#16343a`、操作藍綠 `#267a97`、輔助灰 `#7a9099`，錯誤用 `#9e3f20`。字體沿用 Microsoft JhengHei／既有 sans-serif，不新增字體。桌機左右為編輯及研究預覽，手機改上下排列；文字左對齊，長段落維持約 70 字元閱讀寬度。只用分隔線區分實際任務，不加入裝飾數字、陰影卡片或動態效果。

與本次需求的核對：管理欄位、修訂及錯誤只留在 `/admin`；研究預覽抽取正式閱讀的同一個內容 component，角色、條件與引用保持相同順序。表單及完整 Markdown 可以互換而不丟失輸入；舊修訂衝突保留編輯內容，要求比對後重新讀取。預覽清楚顯示尚未發布，避免將草稿當成讀者正在看的內容。

走查包含正常保存、表單／檔案同內容、stale revision 409、無法登入及手機／鍵盤操作。實際測試結果另由 implementation 記錄，不以本設計文件視為功能已完成。

（2026-10-23：財務補錄已隨公司財報移除，以下為原設計紀錄。）財務補錄沿用上述色彩／字體及左對齊，放在管理維護區的「財務補錄」，不增加一般讀者欄位。畫面依任務排列：JSON／CSV 檔案或文字 → 預覽原始值、倍率、期間、範圍、原幣與既有值 → 勾選已讀官方原文及定位、填理由 → 確認入庫。這是必要的兩階段操作，預覽不得立即寫數值；錯誤保留輸入，修改內容即清除舊預覽，重試沿用原確認 key。桌機表格呈現差異，手機僅表格區可橫向捲動，頁面本身不溢出。專案維持既有視覺，這項功能的清楚差異是可核對的值與文件，無需新增裝飾樣式。

來源健康同樣只在管理區提供「更新一次」與按需展開的來源能力／最近結果；排隊、執行、退避及部分取得分開，明示停機不會持續更新。完成後只刷新對應來源，保留既有分頁與工作位置；不把維護統計或原始佇列加回一般讀者頁。

來源狀態包含多項操作，手機將各來源依名稱、成功時間、狀態、診斷、能力與按鈕上下排列，避免展開能力後必須反覆橫向捲動才能讀完或操作；桌機維持表格。
